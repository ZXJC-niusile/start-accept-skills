# Paper writing

Author the requested text. Explicit user scope, format and existing authorization take precedence over workflow defaults. For a short edit or translation, return the usable text directly; add only requested explanations or material changes in meaning/evidence scope, without repeating caveats already clear in the text. No plan, ledger or handoff is needed. Preserve meaning, numbers, caveats and citation keys.

For new or reassessed scientific claims, use [evidence guidance](../../shared/EVIDENCE.md). For multi-stage work, use [shared principles](../../shared/CONTRACT.md) and [handoffs](../../shared/HANDOFF.md). Load [issue records](../../shared/ISSUES.md) only when tracking prior review findings.

## Work

1. Resolve the manuscript, requested scope, format, audience and source versions. Read adjacent passages and applicable project instructions. For new drafting, identify the paper type and known contributions. Ask only about ambiguities that materially affect the output; do useful independent work meanwhile.
2. Build a short claim-to-evidence map before drafting substantial text. Use supplied analyses or request [analysis](../sa-experiment-analysis/SKILL.md) for unresolved quantitative claims. Unavailable results, references or implementation details stay explicit author-side gaps; do not invent them to complete a section.
3. Choose draft, revise, translate, shorten or outline mode. For full chapters use [section guidance](references/section-guidance.md). Organize around the actual argument; there is no compulsory paragraph, contribution or module count. A theory paper need not acquire an experiment section.
4. Write in precise, natural prose. Retain caveats, mathematical assumptions, numeric values, citations and technical names. Translation and polishing must not strengthen a claim. Consolidate repeated limitations where they qualify the relevant claim; repeat only when a new passage would otherwise mislead. Compress redundant structure before deleting substantive conditions. Match meaningful author style rather than mechanically banning individual words.
5. For review-driven edits, bind each change to its issue and close criterion. Editing is not independent verification that the issue is closed; hand the changed version to [revision check](../sa-revision-check/SKILL.md). Route figure creation or visual edits to [figure production](../sa-figure-production/SKILL.md).
6. Verify the actual diff and nearby consistency: math, citation keys, references, tables, terminology and claim strength. Run available format checks. Follow host policy for standalone LaTeX: save the source, open the built-in editor and compile when supported; otherwise use existing project tooling. Never install a TeX toolchain by default or claim a successful compile without a result.

## Finish

Deliver the revised text or editable source first, then meaningful changes and remaining gaps. Keep analysis notes, translations for the author and issue bookkeeping outside the manuscript. For unfinished drafts use clear author-side missing-input notes; do not present placeholders as measured facts. Use [writing handoff](templates/writing-handoff.md) only when a multi-stage handoff is needed. Stop after the authorized scope is complete; do not start an unsolicited review panel.
